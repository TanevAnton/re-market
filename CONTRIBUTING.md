# Contributing

## Workflow

1. Describe the intended change in an issue when it needs discussion or coordination.
2. Create a branch with a short descriptive name.
3. Keep changes focused and explain why they are needed.
4. Open a pull request with the result and how it was checked.
5. Review and merge once the change is ready.

## Documentation

Separate confirmed requirements from proposals. Record agreed decisions in [the decision log](docs/DECISIONS.md). Update the README when setup or repository structure changes.

## Validation

Check documentation links and preview visual assets. When application code is introduced, document its setup commands and relevant checks alongside it.

## Credentials

Keep credentials and local environment files out of commits. Use placeholder values in configuration examples.
